# WordQuest 项目分析与优化记录

日期：2026-10-30。范围：现有本地应用的数据可靠性、首屏与错误恢复、学习入口、移动端操作和设计一致性。

## 项目判断

项目已有完整的「选词书 → 复习与学新词 → 即时反馈 → 统计与奖励」闭环。React、TypeScript、Vite、Dexie、Zustand 与 ts-fsrs 的职责划分清晰；词库分片、PWA、备份、听力、词根和像素角色提供了可继续完善的基础。

本轮的主要问题集中在数据边界和真实操作状态。继续增加视觉装饰或功能入口，无法解决调度停留在学习阶段、同词多书归属覆盖、备份缺项和首屏等待网络等问题。因此先修复学习与恢复链路，再整理每日行动的层次。

保留「单词勇者 WordQuest」品牌、今日/单词/听力/统计/我的五个导航标签、现有功能入口、像素角色、4 种风格与全部配色选项。设计采用 Operate 模式下的 refinement，取向 3/3/5。

## 问题与落地修改

| 优先级 | 原问题及影响 | 本轮修改 |
|:---|:---|:---|
| P1 | FSRS 快照遗漏 `learning_steps`，短期学习步进无法完整往返 | 保存步进字段，兼容旧版十分钟学习卡，补调度回归 |
| P1 | 同一 word ID 下载到另一词书时覆盖原词书及单元 | 增加 `bookUnits` 多书归属，同词共享学习记录，查询按词书投影单元；修订迁移保留历史记录 |
| P1 | 作答事务外读取旧余额与词卡，交错写入时可能覆盖奖励或重复按新词计分 | 将资料、词卡读取及 FSRS、计分计算移入写事务，补交错回归 |
| P1 | 听力奖励和成就检查并行执行时，余额可能覆盖、成就可能重复发奖 | 奖励与每日汇总共用写事务；成就解锁在事务内重新查重、读取余额并发奖 |
| P1 | 备份缺少设置、库存、任务领奖状态及旧版无日志统计的有效恢复 | 事务化合并，日志按 ID 去重并重放；恢复词书归属、旧统计、外观库存和领奖状态，重复导入不重复加奖 |
| P2 | 每日宝箱按每天从零开始的计数判定，累计碎片奖励不能可靠发放 | 按已开启日期累计，并记录奖励档位；领奖在事务中防重复，历史漏发逐次补齐 |
| P2 | 每次开新一轮重新获得整天新词额度 | 组题减去今日已学新词，多词书之间对相同单词去重；到期复习继续优先 |
| P2 | 全本掌握率漏算重叠核心词，且仅下载部分词书也可能提前通关 | 按多书归属统计掌握词，以全本 3837 词作为分母 |
| P2 | 首次获得经验后进度条仍为零，部分整数升级阈值与公式反解差 1 XP | Lv.1 从 0 XP 起计算；等级判定与展示的整数阈值对齐，覆盖前 50 级边界 |
| P2 | 启动等待完整词库及维护，慢网络影响进入本地界面 | 本地资料先就绪，完整下载、修订和补缺后台执行；共享初始化任务避免重复执行 |
| P2 | 页面分片与数据库加载失败缺乏恢复，切页可能遗留旧滚动位置 | 页面按需加载，添加占位、重试与错误出路；切页重置滚动，首次引导可滚动 |
| P2 | 今日目标与设置含义不一致，行动入口层次较弱 | 显示真实每日新词目标；学习与任务在宽屏双列、小屏单列；概览和七日积累置后，周报不阻挡日常行动 |
| P2 | 配置词书不可用时，首页到期数与实际回退组题不一致 | 词书标题、到期统计和学习队列统一采用有效本地词书，并说明回退 |
| P2 | 按钮未完整传递 ARIA，语义按钮 hover 存在主题对比问题 | 转发原生按钮属性，保留按下/忙碌/标签状态；成对使用填色和文字令牌，增加全局焦点与跳转主内容入口 |
| P2 | 备份、保存、下载反馈不足，自定义数值显示与保存值可能不一致 | 明确忙碌、成功、失败和重试反馈；文件导入使用可键盘操作的按钮；数值限制后回显实际值 |

新设备尚未产生学习进度时，导入备份恢复学习与外观设置；已有学习进度的设备保留本机设置。外观所有权取并集，金币、冻结券、碎片等余额保守取较大值，不把同一份备份反复累加；`deviceId` 始终留给当前设备。这是本地备份合并策略，尚不是完整的多设备账本同步。

## 保留限制与后续顺序

1. **本地优先仍需主动备份。** 尚无云同步；浏览器存储可被用户或系统清理。建议下一阶段明确同步冲突与消耗品账本模型，再接入自动同步。
2. **音频仍依赖系统英语语音。** 尚未生成可分发音频包；优先完善稳定音源与听力材料管理，再增加材料规模。
3. **离线兼容分阶段生效。** 已下载内容可本地使用；其他词书首次下载、旧词书归属修复及完整性补齐需要联网。内置试学词为四级核心词前 300 词。
4. **个性化与分发尚未完成。** FSRS 使用默认参数；分级 TTS、跟读、动态复现和 Capacitor APK 仍在后续范围。
5. **继续验证长周期边界。** 扩充跨设备导入、跨日学习、长期复习和不同系统语音的真实使用验证；不以单次构建通过替代这些场景。
